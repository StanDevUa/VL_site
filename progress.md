# Прогрес розробки — Ресурс 1 (сайт-візитка Вікторії Лемешко)

Робочий журнал: що вже зроблено, які рішення були прийняті і чому, що далі. Оновлюється в кінці кожної сесії. Деталі архітектурних рішень — в `architecture.md`, вимоги — в `tech_specs.md`.

## Зроблено

### Інфраструктура
- Next.js (App Router) + TypeScript + Prisma 6.19.3 (навмисно не Prisma 7 — там прибрали `datasource.url`, ламає поточний підхід) + PostgreSQL.
- Auth.js v5, сесії через **JWT** (не database — Credentials-провайдер це вимагає).
- next-intl (uk за замовчуванням, en/ru); в адмінці локалізація вимкнена — тільки українська.
- Файлове сховище — self-hosted MinIO (S3-сумісне) на сервері Стаса. Це фінальне рішення й для продакшена, не тільки для розробки. В БД зберігаються відносні ключі, а не повні URL (`getPublicUrl()`), щоб можна було міняти розташування сховища без міграції даних.
- Tailwind v4, дизайн-токени в `globals.css` (`@theme`), кольори з дизайн-системи (navy/coral/magenta/violet/blue/indigo/powder).

### Адмінка + публічні сторінки (vertical slices)
Готові повністю (CRUD в адмінці + відповідні публічні сторінки):
- **Мої роботи** (портфоліо)
- **Новини та анонси** — з відкладеною публікацією (без нового поля в БД: існуюче поле `date` використовується як фільтр видимості, `publishedNewsWhere()`)
- **Відгуки**
- **Дипломи** — з перемикачем «Показувати на сайті» (`showOnSite`)
- **FAQ** — з перемикачем «Показувати на головній сторінці» (`showOnHome`)

Усі форми адмінки побудовані на єдиному, вже відпрацьованому паттерні:
- `useActionState` + серверні екшени, що повертають `{ fieldErrors, values }`
- Живе зникнення помилки поля при заповненні
- `LocaleTabs` для трьох мовних версій тексту
- `PhotoPicker` для обов'язкового фото (уся головна фотографія — завжди обов'язкова, це принципове рішення)
- Кастомна серверна валідація замість браузерних popup (`noValidate`)

### UX-полірування адмінки
- Уніфіковані кольори кнопок: `primaryButtonClass` (індиго) / `secondaryButtonClass` (magenta hover — це підтверджено як єдиний правильний hover-колір по всіх реальних макетах, не indigo)
- Курсор-«рука» на всіх кнопках і посиланнях глобально
- Приховані скролбари всюди, окрім `textarea`
- Бейдж **«Приховано»** (сірий, `text-navy-soft bg-navy/5`) додано в списки Відгуків і FAQ — тепер однаково з Дипломами, візуально відрізняється від «На головній» (indigo)
- Підсвітка активного пункту меню в сайдбарі (magenta текст на тій же підложці, що й hover) — винесено в окремий client-компонент `AdminSidebarNav`, бо потрібен `usePathname()`

## Важливі особливості / підводні камені

- **Windows EPERM при `prisma generate`**: якщо в цей момент запущений `npm run dev`, він тримає відкритим `query_engine-windows.dll.node`, і Prisma Client не перегенеровується повністю. Міграції БД завжди проходять коректно через SQL, але сам JS-клієнт треба регенерувати вручну — Стасу потрібно повністю зупинити dev-сервер і перезапустити. Один раз це реально спричинило видиму помилку (поле `showOnSite` показувало не те значення, поки не перезапустили).
- **Дисципліна по обсягу змін**: правити рівно те, що попросили; питати перед будь-яким дизайн/UX-рішенням або розширенням обсягу. Функціональні наслідки вже узгодженого рішення — уточнювати не треба, можна одразу робити.
- Файлові інпути не можна відновити через `defaultValue` — тільки зберігати сам `File` в state і повертати через `DataTransfer`.
- Радіобатони й інші контрольовані інпути після Server Action React може «не домалювати» в DOM — рішення: `defaultChecked`/`defaultValue` (uncontrolled) замість `checked`/`value`.

## Далі

Наступний великий блок — **Магазин**, погоджений порядок:
1. Категорії (адмін CRUD) — найпростіше, потрібне як foreign key для товарів
2. Товари (адмін CRUD)
3. Публічні сторінки: каталог → картка товару → кошик → чекаут
4. Замовлення (адмін) — інтеграція WayForPay + Нова Пошта в кінці, як найскладніше

Навігація «Магазин» в сайдбарі — розкривний пункт одразу під «Головна» (Категорії/Товари/Замовлення нежирним), клік на сам пункт нікуди не веде (аналітика/зведення — на «Головна»).

Після магазину — перехід до самого публічного сайту (за словами Стаса, "перейдем к самому сайту").
